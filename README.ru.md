# egress-autopilot

**Самовосстанавливающийся исходящий VPN для хомлаба.** Один xray-прокси для
всех ваших контейнеров и менеджер, который держит его на рабочем узле:
проверяет активный узел каждые пару минут, переключается за секунды,
предпочитает лучшую подписку и сам возвращается на неё, когда она оживает, —
а обо всём сообщает JSON-событиями, которые можно отправить куда угодно.

[English version](README.md)

```
 ваши сервисы ──HTTP :1080 / SOCKS :1081──▶ egress-xray ──▶ лучший узел ──▶ интернет
                                                ▲
                                          egress-manager ── webhook / exec / файл / API / Prometheus
```

## Зачем

У вас одна или несколько VPN-подписок с десятками узлов vless/vmess/trojan/ss/hysteria2,
и сервер, которому нужен надёжный выход наружу: автоматизации, боты,
качалки, AI-клиенты. Узлы умирают, тормозят, попадают под блокировки,
провайдеры меняют параметры, подписки истекают. Выбирать узел руками в
десктопном клиенте на безголовом сервере не получится.

## Возможности

- **Подписки с приоритетами** — base64/текстовые списки ссылок и JSON-конфиги
  xray (включая цепочки `dialerProxy`); `vless`, `vmess`, `trojan`, `ss`,
  `hysteria2`; REALITY, TLS, ws, grpc, httpupgrade, xhttp.
- **Настоящие проверки** — задержка на «тёплом» соединении, страна выхода,
  спидтест с ограничением по времени; пороги задаёте вы.
- **Быстрый failover** — проверка каждые 2–4 мин, мгновенный переход на заранее
  проверенный запасной, затем поиск по подпискам сверху вниз.
- **Возвращается** — на более приоритетную подписку только после нескольких
  подтверждений, а не по первой удачной проверке.
- **Не паникует** — не переключает, пока лежит ваш собственный интернет;
  рабочий узел, пропавший из подписки, продолжает использоваться; режим
  деградации вместо «интернета нет совсем».
- **Переваривает капризных провайдеров** — стабильный id узла, даже если
  SNI/shortId меняются при каждой выдаче; огромные публичные списки
  проверяются параллельно с ранней остановкой; узлы, которые никогда не
  отвечают, «засыпают» на месяц.
- **Переключение без простоя** через API xray — без рестартов, адрес прокси у
  клиентов не меняется.
- **Мониторинг прямого интернета** (по желанию) — пинг, многопоточный
  спидтест, аптайм.
- **Уведомления — ваши** — webhook, exec-хук, JSONL-файл, REST API, метрики
  Prometheus. Никакого встроенного Telegram/почты: подключайте что угодно
  ([notifications.md](docs/notifications.md), на английском).
- **Компактный** — stdlib Python + xray + curl в Alpine; история в SQLite с
  ротацией; `amd64`, `arm64`, `armv7`.

## Быстрый старт

Нужен Docker с Compose v2.

```sh
git clone https://github.com/motosupamida/egress-autopilot.git
cd egress-autopilot
mkdir -p config
cp examples/config.toml config/config.toml
$EDITOR config/config.toml          # ваши подписки; секреты — через ${ПЕРЕМЕННЫЕ}
echo 'SUB_MAIN_URL=https://provider.example/sub/your-token' > .env
chmod 600 .env config/config.toml
```

Пробросьте переменную в менеджер — раскомментируйте в `compose.yaml`:

```yaml
    environment:
      - SUB_MAIN_URL=${SUB_MAIN_URL}
```

Запуск:

```sh
docker compose run --rm manager check   # проверить конфиг
docker compose up -d --build
docker compose logs -f manager
```

Первый цикл скачивает подписки, проверяет узлы и выбирает один (минута-две;
до этого трафик через прокси отбрасывается). Дальше:

```sh
docker compose exec manager python3 /app/manager.py status
curl -s -H "Authorization: Bearer $(sudo cat data/api-token)" http://127.0.0.1:8765/state
```

Направьте сервисы в прокси (`HTTP_PROXY=http://egress-xray:1080` в
Docker-сети `egress` или SOCKS5 `egress-xray:1081`) —
[пример](docs/configuration.md#use-the-proxy-from-other-stacks).

## Пользователям из России

Рецепт [«выход не в своей стране»](docs/configuration.md#exit-must-never-be-in-your-own-country):
`blocked_countries = ["RU"]` отсекает узлы с выходом в РФ, а проверку «интернет
жив» и домашний спидтест стоит перевести на российские адреса — иначе
блокировка зарубежных хостов будет выглядеть как падение интернета, и
менеджер заморозит переключения.

## Файлы

| Путь | |
|---|---|
| `config/config.toml` | конфигурация (секрет: URL подписок или `${ПЕРЕМЕННЫЕ}`) |
| `data/metrics.db` | история в SQLite: проверки, скорости, пинги, события, трафик |
| `data/state.json` | текущее состояние (активный узел, алерты, таймеры) |
| `data/events.jsonl` | выпущенные события |
| `data/subs/` | последняя удачная копия каждой подписки (секрет) |
| `data/api-token` | сгенерированный токен API (секрет) |
| `xray/config.json` | боевой конфиг xray, пишет только менеджер |

Бэкапить `config/` и `data/`; `xray/` пересоздаётся.

## Команды

```sh
docker compose exec manager python3 /app/manager.py status   # кратко о состоянии
docker compose exec manager python3 /app/manager.py subs     # скачать подписки, показать число узлов
docker compose exec manager python3 /app/survey.py           # проверить все узлы, без переключения
```

Или через API: `POST /action` с `find_best`, `speedtest`, `survey`, `pin`,
`unpin`, `pause`, `resume` ([подробно](docs/notifications.md#actions)).

## Безопасность

- У прокси (1080/1081) **нет аутентификации**. Он есть только в Docker-сети
  `egress`; не публикуйте его в локальную сеть без необходимости.
- API опубликован только на `127.0.0.1` и требует bearer-токен; своего TLS
  у него нет.
- API xray доступен только во внутренней сети между двумя контейнерами.
- Менеджер работает без capabilities, кроме `NET_RAW` (для ping), и с
  `no-new-privileges`.
- `config/`, `.env` и `data/` содержат секреты — права `0600`, в git не
  попадают (уже в `.gitignore`).

## FAQ

**Заворачивает ли весь хост или локальную сеть?** Нет. Это явный HTTP/SOCKS
прокси для того, что вы в него направите. Прозрачная маршрутизация (tun,
tproxy) — вне задачи.

**Можно свои настройки xray (routing, DNS, sniffing)?** Пока нет: боевым
конфигом владеет менеджер. Issues и PR приветствуются.

**Что не поддерживается?** ss с плагинами, hysteria2 с obfs, tuic, ссылки
wireguard. Они видны в выводе `subs` и пропускаются.

**Откуда значения по умолчанию?** Из месяцев работы с несколькими
коммерческими провайдерами и публичными списками на домашнем сервере. Они
намеренно консервативны: без дёрганья и ложных тревог.
